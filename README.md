# AbeloHost Blog

Тестовое задание: небольшой блог на чистом PHP с категориями, публикациями, сортировкой, пагинацией и похожими статьями.

## Функционал

- главная страница с тремя последними публикациями из каждой категории;
- отдельная страница категории;
- сортировка публикаций по дате и количеству просмотров;
- пагинация;
- отдельная страница статьи;
- увеличение счётчика просмотров при открытии статьи;
- вывод категорий статьи;
- три похожие публикации;
- корректные HTTP-ответы `404`;
- адаптивный интерфейс;
- тестовые данные через CLI-сидер;
- Docker-окружение;
- SCSS-сборка через Dart Sass;
- автоматический smoke-тест основных сценариев.

## Стек

- PHP 8.3;
- Apache;
- MySQL 8.4;
- PDO;
- Smarty 5;
- HTML и SCSS;
- Dart Sass;
- Docker Compose.

Приложение не использует PHP-фреймворки и ORM.

## Требования

Для запуска нужны:

- Docker;
- Docker Compose;
- Unix-подобная командная строка.

Проект проверен в Ubuntu 24.04 под WSL2 и Docker Desktop.

## Быстрый запуск

Клонируйте репозиторий и перейдите в его каталог:

```bash
git clone https://github.com/spiff83/abelohost-blog.git
cd abelohost-blog
```

Создайте локальный файл конфигурации:

```bash
cp .env.example .env
```

Соберите PHP-образ:

```bash
docker compose build app
```

Запустите MySQL:

```bash
docker compose up -d db
```

Дождитесь готовности базы:

```bash
docker compose ps
```

Сервис `db` должен перейти в состояние `healthy`.

Установите PHP-зависимости:

```bash
docker compose run --rm \
  --no-deps \
  --user "$(id -u):$(id -g)" \
  --env HOME=/tmp \
  app \
  composer install \
    --no-interaction \
    --prefer-dist
```

Примените структуру базы данных:

```bash
docker compose exec -T db sh -lc '
  MYSQL_PWD="$MYSQL_PASSWORD" mysql \
    --default-character-set=utf8mb4 \
    --user="$MYSQL_USER" \
    "$MYSQL_DATABASE"
' < database/schema.sql
```

Запустите веб-приложение:

```bash
docker compose up -d app
```

Заполните базу тестовыми данными:

```bash
docker compose exec app php bin/seed.php --fresh
```

Приложение будет доступно по адресу:

```text
http://localhost:8088
```

## Тестовые данные

Сидер создаёт:

- 5 категорий;
- 18 публикаций;
- 30 связей между публикациями и категориями.

Повторное заполнение базы с предварительным удалением старых данных:

```bash
docker compose exec app php bin/seed.php --fresh
```

На всякий случай уточню - без параметра `--fresh` сидер не будет изменять уже заполненную базу. 

## Smoke-тест

Проверка основных маршрутов и ожидаемого количества элементов:

```bash
./bin/smoke-test.sh
```

Тест проверяет:

- главную страницу;
- страницы категорий;
- сортировку;
- пагинацию;
- страницы статей;
- похожие публикации;
- корректные ответы `404`.

Для проверки другого адреса его можно передать первым аргументом:

```bash
./bin/smoke-test.sh http://localhost:8088
```

Открытие статей во время теста увеличивает их счётчики просмотров.

## Сборка SCSS

Скомпилированный CSS уже находится в репозитории, так что для обычного запуска Node.js и повторная сборка не требуются.

Установка зафиксированных frontend-зависимостей:

```bash
./bin/assets.sh ci
```

Разовая сборка CSS:

```bash
./bin/assets.sh build
```

Режим наблюдения во время разработки:

```bash
./bin/assets.sh watch
```

Команды выполняются в отдельном контейнере на основе Node.js. Устанавливать Node.js в основной контейнер или на компьютер не надо.

Исходные стили находятся в:

```text
assets/scss/
```

Результат компиляции:

```text
public/assets/css/app.css
```

## Маршруты

```text
/                       главная страница
/category/{slug}        публикации категории
/post/{slug}            отдельная статья
```

Примеры:

```text
/category/php
/category/php?sort=views_desc
/category/php?page=2
/post/many-to-many-mysql
```

Поддерживаемые варианты сортировки:

```text
date_desc
date_asc
views_desc
views_asc
```

Неизвестное значение сортировки безопасно заменяется на сортировку по дате публикации в обратном порядке.

## Структура проекта

```text
app/
├── Controller/          контроллеры публичных страниц
├── Repository/          SQL-запросы и преобразование результатов
├── bootstrap.php        веб-окружение приложения
├── database.php         подключение к MySQL
└── helpers.php          вспомогательные функции

assets/scss/             исходные SCSS-стили
bin/                     сидер, smoke-тест и сборка ресурсов
database/schema.sql      структура базы данных
docker/php/              PHP-образ приложения
public/                  публичная директория Apache
templates/               Smarty-шаблоны
```

`public/index.php` используется как единая точка входа. Для небольшого количества маршрутов сделал простую явную маршрутизацию без отдельного роутера.

Контроллеры обрабатывают HTTP-запросы и подготавливают данные для шаблонов. Репозитории содержат SQL и работу с PDO. HTML находится в Smarty-шаблонах.

## База данных

Используются три таблицы.

### `categories`

Хранит категории публикаций.

### `posts`

Хранит публикации, полный текст, изображение, число просмотров и дату публикации.

### `category_post`

Связывает публикации и категории как "многие ко многим".

Составной первичный ключ не дает сделать повторное добавление одной публикации в одну категорию.

## Похожие статьи

Похожими считаются опубликованные статьи, имеющие хотя бы одну общую категорию с текущей публикацией.

Кандидаты сортируются:

1. по количеству общих категорий;
2. по дате публикации;
3. по идентификатору.

Текущая статья исключается из результата. На странице показывается не более трёх похожих публикаций.

## Счётчик просмотров

Просмотры увеличиваются атомарным SQL-запросом:

```sql
UPDATE posts
SET views = views + 1
WHERE id = :post_id
```

Это чтобы искоючить потерю обновлений при одновременном открытии статьи несколькими посетителями.

## Безопасность и устойчивость

В проекте используются:

- подготовленные PDO-запросы;
- отключённая эмуляция подготовленных запросов;
- автоматическое экранирование HTML в Smarty;
- белый список допустимых вариантов сортировки;
- приведение параметров пагинации к допустимым значениям;
- настоящие HTTP-ответы `404`;
- транзакция при заполнении базы;
- внешняя конфигурация через `.env`;
- раздельная инициализация PDO и Smarty.
